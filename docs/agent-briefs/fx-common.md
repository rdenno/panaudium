# Common brief for all Panaudium FX implementation tasks

Panaudium is an open-source (AGPL-3.0) software synthesizer written in header-only C++17 (MSVC 2022,
also must compile with clang/gcc). Its FX rack is modelled on Omnisphere's: each rack slot hosts one
"unit" (Stompbox, Analog Phaser, Pro-Verb, ...), and each unit has several "models" (e.g. Tube Screamer,
Fuzz Face, Rat) plus up to six knobs. Everything must be synthesized/modelled in code: NO sample files,
NO impulse-response files, NO external libraries (only the C++ standard library).

## Read these files first
- `src/dsp/fx/FxUnit.h` — THE CONTRACT. `FxUnit` base class (prepare/reset/process), and `fxTable()`, which
  defines for every unit type its display name, model list and its knobs with real-world ranges
  (FxKnob::value(norm) converts a 0..1 knob to Hz/dB/s/etc.). Do NOT edit this file. Implement exactly the
  models and knobs listed there for your units, in that order. Always convert knobs with
  `fxKnob(FX_Xxx, i).value(k[i])` (percent knobs come out as 0..1).
- `src/dsp/Dsp.h` — helpers you can reuse: clampf, lerpf, fastTanh, Rng (LCG noise), SineTable/fsin
  (phase in cycles), Svf (TPT state-variable filter: set(fc,q,sr), tick(x,lp,bp,hp), bp(), lp()),
  OnePole, DcBlock, DelayLine (power-of-two ring buffer, init(minSize), push(x), read(delaySamples) with
  linear interpolation; read(d) returns the sample pushed d samples ago, valid for 1 <= d < size-1).
- `src/dsp/Fx.h` — the previous simple Chorus, PingPongDelay and 8x8 FdnReverb; reuse ideas/code freely.
- `src/dsp/fx/FxRack.h` — how a slot calls your unit (for context; do not edit).

## Hard requirements (a test harness checks these)
1. Only edit your one assigned header file. It must stay header-only: everything `inline` or inside classes,
   `#pragma once`, namespace `op`. Keep the existing include lines and the factory function signature.
2. The factory function returns `std::make_unique<YourClass>()` for each of your FX types and `nullptr` for
   every other type.
3. `prepare(sampleRate, maxBlock)` does ALL allocation (size buffers for the worst case of any knob/model at
   up to 192 kHz). `process()` must be real-time safe: no new/delete/vector resize/push_back, no locks, no I/O,
   no exceptions. `reset()` clears state without allocating.
4. `process(L, R, n, k, model)` is in-place stereo, n <= maxBlock (normally 256-512). Output the fully WET
   signal (the slot does dry/wet mixing). Never produce NaN/Inf; flush denormals or add tiny DC offsets where
   feedback loops could decay into denormals; soft-clip (fastTanh) inside any feedback path that could run away
   at extreme knob settings; keep output peaks roughly within +/-2 for inputs within +/-1.
5. Knob changes arrive every block; smooth parameters that would click/zipper (one-pole smoothing per block
   or per sample for gains, delay times, filter cutoffs). Changing `model` between blocks must not crash.
6. Unity-ish loudness at default knobs: with default knobs, wet output RMS should be in the same ballpark as
   the input (0.3x .. 3x), except where the effect is inherently quieter/louder by design.
7. CPU: each unit must run at least ~50x faster than realtime at 48 kHz on one core (stereo). The harness
   flags anything slower than 20x.
8. Each model must sound clearly different from the other models of the same unit (different circuit
   topology, curve, filter voicing, modulation shape, etc.), not just a different default value.
9. Code quality: short comments explaining each model's DSP idea; no dead code; no debug printing.

## Environment limits
You cannot run any shell commands (they are denied, and a denied command aborts your whole run), so do not
try to compile or run anything. Write the code carefully; double-check every identifier you use exists in
Dsp.h / FxUnit.h or the standard library, and that all buffers are sized in prepare(). The maintainer will
compile and run the FX torture test and report problems back.

## Report back
List each unit/model with a one-line description of the DSP you implemented, and any assumptions or known
weaknesses.
